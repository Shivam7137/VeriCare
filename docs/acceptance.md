# Demonstration acceptance

The synthetic backend implements these scenarios using local opaque sessions, PostgreSQL, the persisted mock scheduler, and fake callback/reminder receipts. The matrix links each scenario to executable regression coverage. It does not claim completion of real identity-provider, hospital, telephone/voice, deployment, or patient/staff frontend integrations.

## Additional boundaries covered

- [HTTP tests](../apps/api/test/integration/backend-routes.test.ts) exercise missing/invalid/revoked/expired sessions, strict payloads, malformed JSON, safe storage failures, operator read-only permissions, consent routes, and operator counts for overdue actions/jobs and failed delivery.
- [Interpretation tests](../apps/api/test/agent-tools.test.ts) require explicit UTC intervals and IANA zones. “Thursday afternoon” and “after work” produce clarification prompts without fabricated times. Interpretation performs no task mutations; the exact accepted format is in [contracts](contracts.md#agent-boundary).
- [Worker tests](../apps/api/test/integration/worker.test.ts) exercise due callback delivery, expired-window recovery, and expiry while recipient authorization is locked. A reminder receipt alone never satisfies the callback requirement.
- [Dispatch-race tests](../apps/api/test/integration/dispatch-races.test.ts) block execution when authority is revoked or proposal expiry passes during slot rechecking. [Pool-concurrency tests](../apps/api/test/integration/pool-concurrency.test.ts) exercise simultaneous creations and proposals with a five-connection pool.
- [Migration](../apps/api/test/integration/migrations.test.ts), [schema](../apps/api/test/integration/backend-schema.test.ts), and [isolation](../apps/api/test/integration/database.test.ts) tests check additive upgrades, preserved records, required tables, and isolated test schemas even when database URLs contain connection options.

On a fresh seed, `synthetic-slot-002` starts next Thursday at 14:30 UTC. Existing rows and moved bookings are preserved, so older local records may retain earlier fixture times. Read the scheduler's returned instants and availability before proposing. A phrase such as “Thursday 14:30” is not sufficient booking input until resolved into an actual available slot and explicit time zone. Legacy T001 remains a readable foundation fixture; new tasks exercise the complete workflow.

## Running and retaining evidence

From the repository root with the local database configured in `.env`:

```sh
npm test
npm run test:backend
npm run typecheck
npm run build
npm run format:check
```

`npm run test:backend` loads `.env` and runs the isolated PostgreSQL integration suite. `npm run test:integration` runs the same integration files when `DATABASE_URL` is already supplied by the shell. Tests create disposable schemas; they do not clear the development database or print session credentials. Test-count and live-smoke results belong in [setup verification](setup-verification.md), separately from this coverage matrix.

For a manual synthetic demonstration, retain the task ID and revisions, proposal versions, decision evidence, job delivery events, operation key/status, and scheduler confirmation reference from authorized progress responses. Verify the resulting booking version/slot. Repeat execution with the original revision and confirm that the saved operation and booking version remain unchanged. Keep bearer tokens in the ignored local credentials file, outside evidence reports and Git.

Recovery evidence includes a real executor child-process exit after scheduler commit plus fresh-pool recovery. It does not simulate every operating-system failure or an external provider outage; scheduler response/lookup failures and fake-delivery failures are controlled in-process test injections. No external message or call is made.
