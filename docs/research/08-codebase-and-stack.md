### A3. Risks

1. **Reschedule assumptions**: `agent-tools.ts` `interpretRequest` only understands "reschedule" and explicit UTC windows; `voice-agent.ts` default instructions and tools, `voice-persona.ts` `liveVoiceInstructions`, `scheduler*`, `proposals.ts`, `workflow.ts`, `executor.ts`, `delivery.ts` are all appointment workflow. Do not route journey work through them; `communication_jobs` and `voice_sms` have CHECK constraints that exclude new kinds/templates.
2. **Global scenario env**: one deployment = one scenario; demo of both (appointment pitch + journey) needs a restart or a per-call scenario. `voice_calls` has no scenario column.
3. **Single registered contact per patient** and DOB+name lookup keyed to `emergency_patient_records`; the demo override code `12345678` is a deliberate bypass (fine for demo, say so).
4. **Event sanitiser** silently drops unknown detail keys in `voice_events`.
5. **No inbound SMS** and **no per-recipient opt-out store**: STOP is enforced by Twilio's carrier-level block only (error 21610 on later sends). Record STOP/UNSTOP via the inbound webhook `OptOutType` if Advanced Opt-Out is used.
6. **Provider gating**: real SMS requires `VOICE_MODE=twilio` + `VOICE_LIVE_ENABLED=true` + allowlisted numbers; in simulated mode OTP `sendCode` returns `code_unavailable` (requires `call.mode === 'twilio'`). Journey demo calls must be real Twilio calls, or add a simulated provider path.
7. **File size**: `realtime-bridge.ts` 622, `emergency-lookup.ts` 506, `live-bridge.ts` 564 already near the 600 flag; do not grow them, add new files.
8. **Docs claim** (`docs/demo/emergency-contact-demo.md`): full spoken/keypad verification through to location has not been validated on a real caller-driven call; only SMS delivery was observed.
9. **Residency**: GPT-Live data residency is US/EU only, no Canada (B1). The repo does `store:false`; PHIA/NS residency claims in the pitch must say "synthetic data only" for the MVP.

1. `apps/api/migrations/012_ed_journey.sql`: `ed_encounters` (id, patient_id FK, ctas, status, arrived_at, source, synthetic), `ed_events` (append-only, `kind` CHECK per EdEvent list, `raw` jsonb, `source` hl7v2|fhir|sim, UNIQUE(source, source_event_id)), `sensitivity_flags`, `consent_records` (patient_id, contact name/number fingerprint, scopes text[] status/alerts/estimates, revoked_at), `disclosures` (call_id nullable, patient_id, scope, kind, sentence_hash, allowed, reason, at), `estimate_log` (encounter_id, computed_at, low_min, high_min, basis jsonb, actual_wait_min nullable), `ed_jobs`, `ed_notifications`, `audit_events`. Revoke UPDATE/DELETE on `ed_events`/`audit_events` via trigger raising exception (append-only).
2. Register in `apps/api/src/migrations.ts` and `apps/api/test/integration/migrations.test.ts`.
3. `packages/contracts/src/ed-journey.ts` (+ export in `index.ts`): `EdEvent` zod union, `JourneyStatus`, `EstimateRange`, tool inputs.
4. `apps/api/src/ed-journey.ts`: pure `deriveJourney(events) -> {step, of:5, category}`. `apps/api/src/disclosure-gate.ts`: pure `decide({consent, flags, ctas, lastEventAt, now, scope})` fail-closed (CTAS 1-2, any flag, VIP, deceased, unmapped, feed >15 min, missing consent scope). Tests first in `apps/api/test/disclosure-gate.test.ts`, `ed-journey.test.ts` (no DB).

Day 2 (Nov 12) - ingest and simulator 5. `apps/api/src/opor/hl7v2-mapper.ts` (A04/A08/A02/A03/ORM/ORU -> EdEvent), `fhir-mapper.ts` (Encounter/Location -> EdEvent, `@types/fhir`), `simulator.ts` (synthetic shift emitting both formats, deterministic seed), `ingest.ts` (writes ed_events idempotently, updates ed_encounters, enqueues `ed_jobs`). Tests: `opor-mappers.test.ts`. 6. `apps/api/src/populate-journey.ts` + npm script `demo:journey` in root `package.json`: link demo patients (Maya Chen etc., DOB seeds already in `emergency-demo.ts`) to encounters and consent rows (family contact number from private env, as `seedEmergencyDemo` does; never committed).

Day 3 (Nov 13) - estimates, voice, SMS 7. `apps/api/src/ed-estimate.ts`: patients-ahead / throughput + p25-p75 of replayed synthetic month; suppression rules; fixed sentence templates; writes `estimate_log`. Test `ed-estimate.test.ts`. 8. `apps/api/src/journey-voice.ts` (tools `get_journey_status`, `get_estimate`, reuse identity tools + instructions), edit `voice-agent.ts` (spread tools, dispatch branches, gate call, write `disclosures`), `voice-config.ts` (scenario `journey`), `voice-routes.ts` (scenario selection). Test `integration/journey-voice.test.ts` modelled on `emergency-lookup.test.ts` (unknown patient, wrong code, flagged, stale, CTAS 1-2, prompt-injection string in contact name). 9. `apps/api/src/journey-worker.ts` + one line in `worker.ts`: process `ed_jobs` (recompute estimate; send alert only if range moved >30 min and `alerts` consent; stale-feed check; nurse alert). `ed_notifications` dispatch via existing `SmsProvider`. 10. `apps/api/src/journey-sms-routes.ts`: signed `POST /voice/sms/inbound`: `LEAVING` -> reply with step+range (through gate) and insert nurse-alert row + audit; `STATUS` -> same sentence; anything else -> help text. Register in `voice-routes.ts`. Test `integration/journey-sms.test.ts` with fake signature validation like `voice-sms-routes.test.ts`. Twilio console: set the number's incoming-message webhook to `{VOICE_PUBLIC_BASE_URL}/voice/sms/inbound`; keep STOP/HELP on Twilio defaults.

Day 3-4 (Nov 13-14) - web 11. `apps/api/src/journey-routes.ts` (bearer auth; staff: advance event, set flag, list encounters, predictions vs actuals, alerts; patient: own visit timeline) registered in `app.ts`; add paths to `readPaths`/`writePaths` in `apps/web/app/api/backend/[...path]/route.ts`; test `integration/journey-routes.test.ts`. 12. `apps/web/app/patient/visit/page.tsx` + `components/visit-timeline.tsx`; `apps/web/app/professional/ed/page.tsx` + `components/ed-console.tsx`, `ed-chart.tsx` (SVG or recharts); link from `portal-header.tsx`. Add a web test in `apps/web/test/portal-routes.test.ts` style if time. 13. `apps/web/components/pitch-slides.tsx`: replace/add slides (problem: 10.02% LWBS, gap, demo flow, objections), extend `pitch-live.tsx` panel if tool names are filtered there.

Day 4-5 (Nov 14-15) - verify and record 14. `npm run typecheck && npm test && npm run test:backend && npm run format:check`; update `docs/design/opor-patient-tracking.md` status, `docs/design/contracts.md` (new tools/routes), `docs/setup/phone-setup.md` (inbound SMS webhook, scenario `journey`). 15. Real-call rehearsal (needs `VOICE_MODE=twilio`, tunnel, allowlisted numbers) for: verified daughter call, impostor call, LEAVING text, confidential flag. Record demo; keep fallback screenshots since real-call verification flow is not yet validated end to end.

Cut list if time slips: FHIR mapper (keep HL7 only), recharts (use plain bars), per-patient alert threshold, nurse-alert transfer. Never cut: disclosure gate tests, audit rows, LEAVING flow, suppression for CTAS 1-2.
